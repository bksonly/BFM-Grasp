# BFM-Grasp 交接与演示计划

## 命名与研究贡献

推荐标题：**BFM-Grasp( ): A General-Purpose Dexterous Grasping Function for Code-as-Policies**。

英文：**BFM-Grasp( ): A General-Purpose Dexterous Grasping Function for Code-as-Policies**。

CraftNet 是整体研究系统；BFM-Grasp 是其中负责手指闭环控制的技能。用“通用抓握函数”描述长期定位，不把当前十物体实验写成已经验证任意物体泛化。

一句话：**大模型选择怎么抓，一个共享策略靠触觉把它抓稳。**

贡献重点是层级职责、参考条件与盲反馈闭环的组合，以及经过评估的实现；不把 BFM-Zero、ConTrack、GraspXL 的既有贡献归为本项目原创。

## 建议汇报顺序（约 8 分钟）

1. 先播放十物体同桌抓握，说明同一个 checkpoint、不同参考 z、22 维手指控制。
2. 用一张 pipeline 解释高层选技能和腕部运动、低层触觉闭环的分工。
3. 展示独立批量评估，以及原始参考/ConTrack 参考的对照；区分最后与训练 best。
4. DR 完成后展示标准参考不变、物体几何及位姿变化时的结果。若未达预期，如实报告边界和失败模式。
5. 若完成香蕉入篮，播放真实端到端调用记录，强调可复用接口。
6. 结束于可交接的模型、代码、数据协议、实验账本和下一阶段问题。

展示工程与研究闭环：发现问题、定位原因、做对照、形成可复用交付。汇报正文不讨论个人薪资诉求，不推测此前评价；个人贡献与团队依赖要具体列清。

## “中等规模完成”的验收建议

训练可运行是工程检查，不等于泛化通过。至少进行固定协议的独立 DR 评估，报告各物体、总体与最弱类别；对比 scratch 与 transfer，分开报告训练覆盖尺度组合和未见尺度/扰动种子。所有变体的专家 z 均来自本类标准参考。正式阈值待研究负责人确定，不事后只选择成功指标。

## 香蕉入篮 demo

目标指令：“把香蕉放进篮子里。”第一版只验证已知场景的语言任务编排，不冒称任意场景视觉定位。

1. 高层接收任务和场景描述，输出受限的结构化调用：选择香蕉抓握参考、接近、抓稳、移动到篮子、释放。
2. 腕部轨迹由外部执行器实现；规划坐标来自哪里要在视频中标注。若使用仿真真值，应明确标注。
3. BFM-Grasp 以标准参考 z 控制手指，移动阶段保持触觉闭环。需要验证当前按帧更新 z 在搬运阶段的保持方式，不能直接假设整段训练参考循环即可。
4. 释放可采用规则控制，平滑回到张开手势。该阶段标注 rule-based release。
5. 成功判据为物体进入篮子容积并稳定停留；碰撞、掉落、超时均记录。保存高层原始响应、解析后的调用、执行状态和未剪辑视频。

接入实际模型前需要确认可调用的 API 模型名称和认证方式；不假设桌面聊天模型名称一定是可用 API 标识。API 密钥只通过运行环境注入，不写进仓库或页面。当前未接入模型，也没有该 demo 视频。
